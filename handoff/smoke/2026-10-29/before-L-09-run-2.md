Explain quickly why 0.999... equals 1. Don't save anything.

## Tutor 1

**Short answer:** 0.999… (the 9s going on forever) is not "just below" 1 — it *is* 1, written differently.

**The subtraction trick.** Call the number x:

- x = 0.999… (9s forever)
- Multiply by 10: the decimal point just shifts, so 10x = 9.999…
- Subtract: 10x − x = 9.999… − 0.999… → the endless 9s after the decimal cancel, leaving 9x = 9
- So x = 1.

**Why people resist it:** the intuition that 0.999… is "the biggest number less than 1" is the mistake. There is no biggest number less than 1 — between any two different numbers there's always another (their average, for example). There's no number at all between 0.999… and 1, so they can't be two different numbers.

Optional check if you want to test it yourself: what does 1/3 × 3 give you if you write 1/3 as 0.333…?

I don't buy it. It's always a tiny bit less.

## Tutor 2

That "tiny bit" is exactly the thing to pin down — so let's put a number on it.

Your picture works if the 9s **stop**. 0.999 is 0.001 short of 1. 0.9999999 is 0.0000001 short. Any decimal that ends is genuinely less than 1, by a gap you can write down.

But 0.999… doesn't end. The "…" means there is no last 9. And here's the trap: to be "a tiny bit less," there'd have to be a specific gap — a number you could write down for 1 − 0.999…. Try to name it:

- A millionth? 0.999… already has way more than 7 nines, so it's closer than a millionth.
- A billionth? More nines than that too.
- Any positive gap you can name, no matter how tiny — 0.999… beats it, because the 9s keep going past any fixed count.

So the gap can't be any positive number. And it can't be negative, because 0.999… isn't bigger than 1. The only number left is **zero**.

## Tutor 3

Here's a completely different route, using thirds.

Do the long division for 1 ÷ 3. It never terminates: 0.3333…, with a remainder of 1 every single step, forever. So:

**1/3 = 0.333…**

Now multiply both sides by 3:

- Left: 3 × (1/3) = 1
- Right: 3 × (0.333…) = 0.999…

Both sides are the same number multiplied by the same thing, so they must still be equal: **1 = 0.999…**.

The punchline is that these are two *names* for the same number — like 2/4 and 1/2. Neither is "a bit less" than the other; the decimal notation just gives you two ways to write the same point on the number line.

Good stopping point. The two ideas worth keeping: the 9s never end, and any gap you can name is already beaten. Happy to pick this up again next time if you want to test it on something like 2.999… or 0.4999….
